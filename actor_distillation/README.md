# Actor self-distillation (on-policy selection-distillation)

Fold the **best-of-5 + reward-model** selection gain back into the **actor's
greedy (n=1)** output. Product = a better actor, not a better judge. This is
the "stage A–E" loop referenced in the top-level README, extracted from the
MolmoWeb era (`browser_agents/browser-environment`, May–Jun 2026).

```
for round in 0,1,2,...:
  A. sample 5 actions/state from the CURRENT actor (temp 1.0)      pilot_actor_infer.py
  B. judge picks 1 of 5 (trained 4B selection ARM — no GPT, $0)    run_selector_offline.py
  C. build SFT: {actor_prompt(state) -> selected action}           build_onpolicy_sft.py
  D. SFT the actor to GENERATE the selected action                 train_actor_sft.py
  E. eval: actor GREEDY (n=1, no judge) on OM2W
```

Alternative stage B (offline, no serving): `../data_generation/molmoweb_actor/
build_distill_selections.py` — argmax of stored GPT-5.5 PRM scores with a
0.7 quality floor and consensus tiebreak. Same output schema
(`{state_id, selected_orig_idx, ok}`), interchangeable with the ARM selector.

## Run order

**Pre-check first (GO/NO-GO, no training):**
```
python onpolicy_precheck.py --candidates <A>/candidates.jsonl --selections <B>/selections.jsonl
```
Measures how often the judge picks OFF the actor's plurality action — that
disagreement IS the distillable headroom. Rule of thumb: <10% off-plurality →
little to distill; >25% → worth running the loop.

**Stage A** — `onpolicy_gen.qsub` → `pilot_actor_infer.py`. Samples n=5 per
state at `PILOT_TEMP=1.0 PILOT_TOP_P=1.0` (RM *training* data used 0.7/0.8;
distillation used 1.0 for extra diversity). Chunkable via
`PILOT_NCHUNKS`/`PILOT_CHUNK` (strided). Resumable (skips state_ids already
in `PILOT_OUT`).

**Stage B** — `onpolicy_select.qsub`: serves the merged selection ARM with
vLLM, then `run_selector_offline.py` calls `catts_vision_select_v2` (imported
from `../inference/selection_prompt.py`, the byte-exact training prompt) over
each state's 5 candidates with a deterministic per-state shuffle
(`random.Random(state_id)`) to kill position bias. Out:
`{state_id, selected_orig_idx, ok, raw}`.

**Stage C** — `build_onpolicy_sft.py` joins A+B → `{state_id, screenshot,
prompt, target}` rows where `target` is the WINNING candidate's raw molmo
JSON. Flag `--only-changed`: keep only states where the selected action
differs from the actor's plurality action (don't burn gradient reinforcing
what the actor already does).

**Stage D** — `run_train_actor_sft.qsub` → `train_actor_sft.py`. Plain
causal-LM SFT of MolmoWeb-4B (LoRA all-linear r=16, vision tower excluded,
prompt tokens masked to -100, lr 1e-4, 1 epoch). The actor's native prompt is
reused verbatim from the candidate file so train == generation distribution.

**Fully-online variant** — `onpolicy_online.py`: 2 GPUs, streaming.
GPU0 = actor (generates AND takes one SFT step per batch), GPU1 = frozen
vLLM selector. Every batch is generated by the just-updated weights (true
on-policy). Supports `KL_COEF` anchoring to the frozen base actor. This is
what produced the 8k-state run below.

## Gotchas / knobs

- **Anti-collapse**: SFT can kill the sample diversity that best-of-N needs
  next round. Keep epochs low; `KL_COEF` anchors to the base actor.
- **Ceiling**: best-of-5 only helps if a good action is among the 5 — gains
  are bounded by actor sample diversity (the pre-check measures this).
- **States are gold-trajectory states** + on-policy actions (cheap, no live
  browser). True DAgger would roll the actor out for its OWN states.
- **External dependency (documented, not vendored):** stage A and the online
  variant import `MolmoWebAgent` from the production tree
  (`browser_agents/browser-environment/eval/agents.py`) for `_build_prompt` /
  `_parse_molmo_output` — the actor's prompt must be byte-identical to the
  live harness, so we reuse the real builder rather than approximate it.
  Everything else in this directory is standalone against this repo.
- The qsub wrappers keep their original SCC paths/envs as a faithful record —
  edit `PROJECT_DIR`/conda env for your cluster.
